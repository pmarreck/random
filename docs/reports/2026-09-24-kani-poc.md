# Kani Rust proof of concept — 2026-09-24

The real `Fixed::from_parts` constructor passes three implementation properties
over every i64 mantissa/i32 exponent pair (2^96 combinations):

1. Acceptance is exactly `(m == 0 && e == 0) || (2^62 <= abs(m) < 2^63)`.
2. Accepted pairs are preserved without modification.
3. Accepted values satisfy the production canonical-validity predicate.

The independent acceptance predicate widens to i128 before taking magnitude;
it does not copy production wrapping-i64 arithmetic. There are no assumptions,
stubs, or sampled inputs. The reachable constructor path has no loops or recursion.
The harness specifies unwind 2 and leaves unwinding assertions enabled.

## Falsifiable evidence

`TMPDIR=/dev/shm ./verify-kani` builds each control independently and serially.
The wrong contract includes the upper endpoint `2^63`: Kani rejects it because
the actual constructor correctly rejects `i64::MIN`. The gate requires exactly
this named assertion failure, not just a nonzero exit. The corrected contract
passes all 100 checks and five explicit covers: canonical zero, both signed
canonical endpoints, rejected minimum mantissa, and noncanonical zero.

The gate requires all three named assertions and all five reachable covers.
Its ordinary Bash test rejects malformed, missing, vacuous, unknown, timeout,
unsupported, and wrong-failure evidence. These classifier controls are not
substitutes for the real red/green solver runs.

Final formatted-source evidence is retained at
`/dev/shm/random-kani.AW9ozb`: exported JSON, full logs, GNU time measurements,
base revision, and SHA-256 fingerprints of source and environment definitions.
Base revision: `436f512eebf2ae705f852c9edeceb68e1d495519`, with the POC additions
in the working tree identified by those hashes. RAM evidence is temporary;
rerun the command to reproduce it rather than relying on that directory forever.
The [versioned evidence summary](../../verification/kani/2026-09-24-evidence.json)
preserves the actual checks, tool versions, backend statistics and source hashes.

## Tooling and trust boundary

- Kani 0.68.0; matching Rust nightly 2026-08-21, reporting rustc
  1.100.0-nightly (8925ea358, 2026-08-20).
- CBMC 6.11.0 and its bundled MiniSAT (no separate solver version reported).
- x86_64 Linux, `randomr` library with no default features; normal production
  Rust 1.97.1 remains unchanged. This is verification through Kani's compiler,
  not a proof of the compiled shipping binary.
- Release archives and compiler components are hash-pinned in `nix/kani.nix`;
  Nix dependencies are locked by `flake.lock`. No global rustup installation.
- Private offline Cargo home, separate control targets, one compiler worker,
  240-second timeout with a five-second kill fallback, and a 4 GiB **per-process
  virtual-memory** limit, not an aggregate RSS limit.

The compiler, verifier translation, backend, and specification are trusted.
No user flags disable Kani checks. Kani itself supplies backend defaults that
disable some raw CBMC C checks; Rust overflow checks are enabled by Kani's
compiler. Consequently this is not a claim that every possible CBMC check runs.
Optional source coverage is off; explicit `kani::cover!` checks are on.

## Cost and review

The final positive run took 8.42 seconds including compilation, with 294,256 KiB
peak RSS reported by GNU time; the negative run took 8.27 seconds and 294,008 KiB.
A separate backend-only
profile of the same instrumented proof took 0.43 seconds and 27,792 KiB peak RSS
(CBMC including its solver; not a solver-only allocation measurement).
Raw CBMC exits 10 on Kani's cover and internal reachability instrumentation;
only the interpreted Kani result is used as the proof verdict.

A fresh-context reviewer independently derived the contract, inspected actual
positive/negative exports, and ran the gate tests. No blocking findings remained.
Suggestions incorporated: pin all three assertions, include flake fingerprints,
retain evidence outside Nix-shell temporary lifetime, add kill fallback, and
state the memory limit accurately. Review record:
`/tmp/dispatch-log/random-kani-review-final.md`.

Normal Rust library tests: 29 passed, 0 failed, 0.26 seconds. No production
arithmetic, seeded output behavior, SIMD implementation, or Lean work was changed.
`nix develop -c ./test` passed all 27 suites in FAST mode, including the
cross-implementation differential and 1,060 continuation checks. The deep JIT
differential is intentionally skipped in FAST mode. The suite also built and
checked the release binaries; no independent CI result is implied here.
An additional minimal Nix sandbox exposed an unpatched helper shebang (exit
126). Invoking that helper through the declared Bash interpreter fixes the
test integration without changing the proof or its acceptance predicate.

## What this does not prove

No cryptographic-security, entropy-quality, distribution-bias, whole-library,
SIMD, floating-point, other-platform, or compiler-correctness claim follows.
This is a useful small demonstration of verifying existing Rust without
rewriting it in a proof language. A next bounded target could be cursor
encoding/decoding or checked offset arithmetic, with its own independent contract.
