# Zig Port Implementation Plan

> **For agentic workers:** Follow the checked task sequence and keep each
> control mechanically capable of failing. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Port the integer-only numeric kernel to Zig 0.16, expose it through a C FFI, and ship a `randomz` C CLI — with `bin/random` retained permanently as an independent differential oracle.

**Architecture:** `src/fixed.zig` (pure, no I/O) → `src/randomz.zig` (pure RNG/distributions) → `include/randomz.h` (C FFI) → `randomz` (C CLI, dogfoods the FFI) + `drandomz`/`nrandomz` aliases via argv[0] dispatch. The Zig core performs no I/O; stdin/stdout and environment handling live in the C CLI.

**Tech Stack:** Zig 0.16, C11, Nix flake, `bc` (independent oracle), the existing LuaJIT implementation (differential oracle).

---

## Global Constraints

- **Read `ZIG_RECENT_API_CHANGES.md` first.** The former 0.15-to-0.16
  migration note was consolidated into that root guide. Live items include:
  `linkLibrary` lives on the **module**, not `Build.Step.Compile`; `b.path()`
  not `.path`; and `@export` requires a pointer.
- **Verify against the shipped stdlib, not the notes.** When a doc and the
  compiler disagree, inspect the pinned Zig stdlib and believe the compiler.
- **Default to ReleaseFast for shipped artifacts, ReleaseSafe for tests.** In `build.zig` do NOT use `b.standardOptimizeOption(.{})` (it defaults to Debug). Use:
  `const optimize = b.option(std.builtin.OptimizeMode, "optimize", "...") orelse .ReleaseFast;`
  A ReleaseFast test suite compiles out safety checks and cannot observe UB.
- **Debug builds must announce themselves** in yellow on stderr, suppressible via `MUTE_DEBUG_STATUS`.
- **Representation, identical to `lib/fixed.lua`:** `value = m · 2^(e−62)`, `m: i64` with `2^62 ≤ |m| < 2^63` for nonzero, canonical zero `(0, 0)`, exponent `e: i32`.
- **Truncation toward zero, everywhere, unconditionally.** Use `@divTrunc`, never `@divFloor`. This is the single most likely source of silent divergence from the Lua reference — the two differ exactly on negative inexact operands, and the Lua side has pinned exact-value tests for that case.
- **The C CLI must not `@import` the Zig module.** C physically cannot, which is why the CLI is C: the bypass is inexpressible rather than merely discouraged.
- **`flake.nix` currently pins LuaJIT to `28084004`** (the `#1499` fix). Add Zig without disturbing that.
- Flakes only see git-tracked files — `git add` new sources before wondering why `nix build` cannot find them.
- Tabs. Never commit red. Commits carry no "Generated with Claude Code" or Co-Authored-By.

## What you are porting

`lib/fixed.lua`, 1811 lines, 20 public functions: `mul128`, `norm`, `mul`, `add`, `sub`, `neg`, `cmp`, `from_int`, `to_int_trunc`, `frac`, `div`, `ln`, `exp`, `cos_turns`, `sqrt`, `pow`, `parse`, `parse_int`, `parse_int_safe`, `tostring`. Guarded by 216 checks in `tests/fixed_test.lua` plus a `bc` sweep at 650+ cases per function.

## Read this before writing any code

**The previous plan's code was wrong on fourteen of fourteen tasks**, including a `div` that overflowed for every input, an unnormalized constant that crashed an assert, an `add` that returned a false zero, an `exp` that hung forever, a `sqrt` exponent off by exactly 2^31, and a legacy range-sampler fix that reintroduced the very hang it was written to remove. Two independent audits then found three more merge blockers and five vacuous controls.

Treat every code block in this plan as a **starting point, not gospel**. If a test fails, check whether this document is wrong before assuming you mistyped. If it is wrong, say so with evidence.

**Things that were wrong specifically because nobody re-ran a claim:**
- A benchmark baseline that measured a partial `jit.off` and called it a full one.
- Two "LuaJIT bugs" written up from a harness that hashed pointer addresses (`tostring()` on cdata prints a boxed address, not the value).
- A version constant naming a build that had been *measured reproducing* the bug it claimed to be fixed in.

**The rule that caught all of them:** re-run the claim, don't re-read it.

## Task 2: Core — `mul128`, `norm`, `mul`, `from_int`, `to_int_trunc`, ~~`frac`~~

> **Plan correction (2026-08-02):** `frac` is listed here but cannot be done
> here. `M.frac` is implemented as `M.sub(m, e, M.from_int(to_int_trunc(m, e)))`
> — it depends on `sub`, which is Task 3. Moved to Task 3 rather than pulling
> `sub` forward, so each function still lands with a differential that can
> actually verify it.

- [x] Port. Zig has native `u128`, so `mul128` is a single multiply rather than four 32-bit partials — but the *result* must match the Lua synthesis bit-for-bit. Verify, do not assume.
- [x] The i32 exponent contract is free here: `e: i32` makes out-of-range unrepresentable. But `e1 + e2` **panics on overflow in ReleaseSafe** where Lua silently produced a wrong value — decide deliberately whether to saturate, error, or let it trap, and document which. The Lua side asserts; match that behavior.
- [x] `norm`'s leading-zero count uses `@clz` rather than Lua's shift loop. Confirm identical results including at `INT64_MIN` and canonical zero.
- [x] Extend the differential to cover these. Sweep the mantissa extremes (`2^62`, `2^63−1`) and both signs.
- [x] Commit.

## Task 3: `add`, `sub`, `neg`, `cmp`, `frac`

- [x] Port. The Lua `add` splits on sign: opposite-sign addition is exact (magnitudes shrink, cannot overflow); only same-sign needs the pre-shift. **That split is load-bearing** — the naive version returned a false canonical zero for a true 1-ULP difference. Preserve it.
- [x] Port `frac` here, not in Task 2: it is defined in terms of `sub`.
- [x] Pin the same-sign 2-ULP worst case the Lua side pins, and the `d = 62/63/64` exponent-gap boundaries.
- [x] Commit.

## Task 4: `div`

- [x] Port the bit-serial division. **`@divTrunc`, not `@divFloor`.** The Lua side has six pinned negative-operand exact-value tests precisely because a floor-vs-truncate mutant passed its entire suite including the `bc` sweep — the sweep provably *cannot* detect rounding direction, because for random operands the two error distributions are identical.
- [x] The differential must include negative operands in both positions. A positive-only sweep was blind to half the domain for five tasks.
- [x] Commit.

## Task 5: `ln`, `exp`

- [x] Port. Constants (`LN2`) must match the Lua values exactly — regenerate from `bc` and compare rather than copying.
- [x] `exp`'s correction loop is bounded (`EXP_MAX_CORRECTIONS = 3`) and errors rather than spinning. The natural maximum is 2; 3 is deliberate headroom. Preserve both the bound and the loud failure.
- [x] Zig's `i32` exponent makes the `k` overflow that caused the Lua hang unrepresentable — verify that is actually true rather than assuming, and that the failure is a trap or a returned error, not a wrong value.
- [x] Commit.

## Task 6: `cos_turns`, `sqrt`, `pow`

- [x] Port. `cos_turns` reduces quadrants **in turns**, exactly, with no `2π` multiply in the reduction. Preserve that — it is the single largest rounding source removed.
- [x] Term counts: 20 (atanh in `ln`), 16 (`exp`), 14 (`cos`/`sin`). Two of those were raised after measurement proved the original claim wrong; do not lower them without measuring at the domain's worst point.
- [x] `sqrt` uses an integer seed plus soft-float Newton refinement — pure-integer Newton on the mantissa caps at ~31 bits.
- [x] Commit.

## Task 7: `parse`, `parse_int`, `parse_int_safe`, `tostring`

- [x] Port the decimal I/O. No `strtod`, no `printf("%f")` — that is the whole point.
- [x] `tostring` must render the integer part without a double round-trip. `parse` and `tostring` share a documented magnitude limit so they cannot disagree; there is a round-trip test at and beyond 2^63.
- [x] Commit.

## Task 8: C FFI — `include/randomz.h`

- [x] Expose the kernel and caller-owned BLAKE3 DRBG state `(key[32], byte_position)`
      as a C ABI. Derive keys with the versioned KDF and use keyed empty-message
      XOF seek; `@export` requires a pointer in Zig 0.16.
- [x] The core stays pure: expose explicit get/set of raw DRBG state so callers can round-trip it without the core touching a file.
- [x] Commit.

## Task 9: `randomz` C CLI + symlinks

- [x] Preserve the full flag surface. `--about` follows the fleet one-line format (name, version, platform, arch).
- [x] **`$IFS` must not influence output** — the Lua side had a determinism hole there.

## Task 10: The differential at CLI level, and `./bm`

- [x] Add `tests/randomz_test` to compare `randomz` against `bin/random` over a 97-case seed × flag × stdin matrix, requiring successful nonempty byte-identical stdout, and run the existing Bash CLI/DRBG suites through a configurable executable selector. A separate C-compiled conformance program checks the public header, layout, callbacks, statuses, and every exported symbol. This is the payoff control: two independent implementations, no shared code.
- [x] **`./bm` covering all three implementations** — LuaJIT, Zig/C, and Rust,
  with byte-identical seeded preflight across raw/encoded output, uniform ranges,

  CPU/wall measurements, exact binary/toolchain identities, and two-sided
  ±15% review notices; `--quick` and parity-only `--check` are available.
- [x] Cross-target digest control: the raw Zig kernel and the 42-invocation C CLI payload are byte-identical across native x86_64-glibc, native x86_64-musl and qemu aarch64-musl; every C CLI leg also matches the LuaJIT oracle. The required compile gate additionally covers aarch64-macOS plus both x86_64-Windows and aarch64-Windows.

## Standing requirements for every task

- **Mutation-test every guard you add.** Break the thing it protects, confirm failure on **10 consecutive runs**, restore, confirm 10 passes. This project shipped five guards that could not detect being broken; four were found only by mutation.
- **Deterministic controls, never probabilistic.** Three separate behavioral checks had to be replaced because they asserted a JIT- or timing-dependent outcome. If the symptom is nondeterministic, assert the invariant instead.
- **Test filters as classifiers over sets**, not predicates over examples. An 8-input hand-picked comparison reported "identical" for three libm functions that a swept comparison proved diverge.
- **`bc` is the independent oracle** for math; `bin/random` is the independent oracle for behavior. Never derive an expected value from the code under test.
- Report exact numbers. Several reports in the previous plan misstated their own sweep composition and assertion counts.
